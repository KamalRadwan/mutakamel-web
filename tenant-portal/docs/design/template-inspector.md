# Template element properties

T02 R6 inspector source is applied on Main as of 10 November 2026. The current Portal route needs a qualified native adapter to enable the bound inspector.

The qualified ribbon host renders `TemplateDesignInspector` in a centered dialog. `TemplateDesignInspectorDialog` provides a standalone wrapper. All controls use the Portal design-system barrel and the real i18n provider, with separate Arabic and English copy, logical spacing and theme tokens.

A bound host must supply the current canonical bridge, a qualified native validator, the current scoped asset list and the owner field projection. It subscribes to authored document and selection changes. T01 owns `useTemplateDesignEditor`, the bridge, gesture controller and numeric/graph geometry. The inspector never creates another authored store or transport.

The bridge contract is a structural subset of UI04: `read`, `context`, `canEdit`, `selection`, `select`, `execute`. R2's actual canonical store remains the history authority. The T01 controller supplies `resizeNumeric`, `group`, `ungroup`, `layer`, `flags`. There is no copied drag, resize, snapping, or graph engine.

An open property form retains local input until Apply. Apply compares owner context, generation, selection, original selected node and document direction against the latest canonical state. It rejects lost authority, an active gesture, a locked node/ancestor or stale state, then performs full native admission and submits the normalized admitted document as one `EDIT_DOCUMENT` command. One undo restores the entire property change. Unrelated node edits survive. Discard restores the latest authoritative element and creates no history entry. Saving uses the existing R2 save/receipt/recovery transport; no new API or simulated acknowledgement exists.

Supported controls:

- Plain text, font token, size, weight, alignment, line height, letter spacing, text/background color, opacity, borders and logical padding. T14/UI06 owns rich-text content editing through the additive RichTextEditor component port, outside the property form. Reset removes only element style overrides.
- Canonical document direction AUTO/RTL/LTR. Schema V1 has no per-node direction property.
- Image replacement from supplied active scoped assets, alternative text/decorative state, object fit and normalized focal coordinates. Image rotation and millimetre frame changes call T01's numeric geometry controller. The inspector reads the existing protected assetContentHref route with an unoptimized same-origin image, and shows a failed-access boundary. Exact crop placement requires the host to provide T06's qualified `computeImageCropPlacement` and a current decoded-source/style-bound content frame. When that port is absent, the preview shows the original image and marks exact cover crop as pending. No substitute CSS focal-position formula is used.
- Static/dynamic table column widths and units, alignment/wrapping/visibility, header/cell typography/colors, value bindings and number/currency precision, row splitting, repeat headers, striping and empty-table rules. Static rows expose text/binding cells and fixed row heights. Structural insert/delete/reorder preserves cell IDs, formulas and binding ASTs. Dynamic table header/footer band grids receive corresponding column edits.
- Static rectangular merge/unmerge. The first cell value is retained, other removed values are explicitly disclosed, and Discard/Undo restores the original data. Insert/delete adjusts crossed spans; moves crossing a merged span are refused. V1 requires at least one anchored cell in each row, so a merge/insert that would produce an entirely covered row is refused rather than weakening the owner schema.
- Totals labels, order, binding/format, emphasis and visibility. All financial values still come from owner APIs. No accounting/tax/business calculations are implemented.
- Layer selection includes hidden and fixed-page-only nodes. Lock/hide/show/unlock, ordering, grouping and ungrouping invoke T01's canonical controller.

Native provider absence is an unavailable boundary. Editing additionally requires current owner/source/checksum admission metadata and the actual descriptor-bound native validator; the metadata is a UI freshness fence and is not authority. Portal projected fields never become a fabricated full descriptor. Read-only/pending/gesture/context loss disables inputs, portalled selects and checkboxes, with current checks repeated at command time. Font choices and optional build/checksum information require a qualified native catalogue supplied by the host. The applied host leaves font and exact crop ports pending. The current proven font catalogue contains SYSTEM_SANS, ARABIC_SANS and SYSTEM_SERIF (DejaVu builds). Cairo/Plus Jakarta print support is a font-owner dependency; the UI must not label those tokens as unqualified fonts. Main has `@mutakamel/template-schema@0.0.9-t12-union.1` installed, and its browser-safe entry exports `validateDescriptorModel`. Provider mounting, bundled browser identity verification and actual owner admission remain pending. Runtime rebuild remains a separate release gate.

Focused verification uses the actual current Main canonical store, native schema source and installed real Portal dependencies. Hook tests cover local input/apply/discard/stale forms; static markup checks cover both languages. The accepted R6 jsdom case mounts the real currency control and checks its unavailable message when qualification returns zero paths and disallows inherited currency. Full dropdown interaction, authenticated browser interaction, backend save/reload, light/dark screenshots, image comparison and print/PDF remain pending after the qualified adapter and runtime leases.

R2 includes all actual V1 value formats: TEXT case transformation; NUMBER min/max fraction digits and grouping; CURRENCY path/precision; PERCENTAGE; DATE; DATETIME; BOOLEAN display labels. New formats must be allowed by the current owner's field projection, and native descriptor-bound admission still decides whether the candidate is valid. Data-field formatting, table binding and totals formatting all reach the same atomic command.

`extensions` contains React component types `RichTextEditor` (T14), `BindingPicker`/`CellValuePicker` (T15), and `Feedback` (T20). Rich text is mounted outside the property form; binding/value picker callbacks stage typed data locally rather than issuing another save. T02 installs no imperative focus manager. T13/UI05 pages are independent. These additive ports avoid peer overwrites of inspector source.

`onLocalStateChange` reports owner/node identity, dirty/stale/disabled state. The host must aggregate pending local property/content sessions when deciding Save, preview, external selection and navigation. The dialog itself guards closing until Apply/Discard, and pending properties disable local layer/geometry changes. Authority revocation still removes protected content immediately. Mixed layer lock/hide is represented as an indeterminate checkbox state rather than false.

R3 normalizes cleared/whitespace optional node names by omitting the field, enforces the actual native 120-character maximum, and labels unnamed layer entries with translated type and explicit-locale Western ordinal. Positioned arrangement controls precheck the existing T01 known Flow/root/subtree-lock/visibility/zIndex limits; the real native controller still performs full graph/page admission. Divider color/thickness/style edits use canonical props consumed by the renderer. No lowercase/three-digit color fallback is introduced: actual native six/eight-digit normalization remains authoritative.

R5 consumes T15's actual shared DataEligibilityPort through the host's optional eligibility prop. Its native-qualified paths and allowContextCurrency flag replace local candidate enumeration and the inherited-currency prerequisite. Explicit optional display pairs can qualify while ambient currency remains unavailable. Current/writable receipts and matching descriptor checksums fence the menu; missing/stale/unsupported qualification preserves existing pins and closes replacement. The projection never creates eligibility or a descriptor. Choosing a path additionally validates the exact binding in the complete local draft before staging. Full Apply and native formula/MONEY/UNIT_PRICE refusal remain unchanged. The host must supply shared eligibility and the descriptor-bound validator from the same current qualified source/native context and retire them together.

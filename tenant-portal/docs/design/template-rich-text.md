# Template text authoring / UI06 R2 candidate

R1's paragraph/list/token/link/grapheme editor remains the current-admitted source behavior. R2 adds an editor-owned interlock and the semantic heading adapter requested for MVP. No source is applied or mounted, no runtime or package was changed, and the current native schema still refuses headings.

The proposed heading AST and exact Schema/Compiler/T05 changes are specified in `HEADING-EXTENSION-PROPOSAL.md` in the private integration packet. A heading is a real heading block with level 1..6, not paragraph styling or raw HTML. Paragraph/list/heading conversion preserves runs, marks, tokens, link targets and alignment; list unwrapping retains every paragraph. Default heading controls remain disabled until root qualifies the complete schema/compiler/measurement stack. Native admission is mandatory even when controls are enabled.

The host opens a native-admitted RichSession and acquires a `createRichTextHostInterlock().acquire(session)` lease before mounting StructuredTextEditor. The component requires that lease; it reports pending/composing state. Apply/Discard releases it. The host owns explicit close/owner-replacement/disposal; unexpected unmount leaves the session fenced until the host resolves pending content. React StrictMode cleanup must not implicitly release another owner layer's lease.

T01 gates external canonical commands, page/selection navigation, Save/recovery and global Undo/Redo through `interlock.runExternal`. T13 PageHost.canEdit combines actual write authority with no active local text session, and its controller refreshes on fence changes. Its read-only page navigation must also be guarded: canEdit alone does not block navigate(). Pan/zoom/rulers/print bounds remain viewport preferences. T02's permitted appearance editing can retain a text session; Apply merges content into latest styles, while conflicting content changes correctly refuse as stale.

Inline hardBreak (Enter/paste) and sibling pageBreak (T13's node-boundary command) are distinct. No caret-based graph split or source-offset inference is added. Bindings remain owner-qualified supplied tokens; no path/business API is invented. Existing native source-offset/grapheme/link-protocol/lock/authority/refusal checks remain authoritative.

The exact Tiptap root pins and complete public metadata/peer closure are in `TIPTAP-EXACT-CLOSURE.json`; this is review evidence, not an installed lock or browser-compatibility proof. Root/T12 must qualify that adoption separately. Headings/native/browser/print/PDF and authenticated save/reload remain explicit owner gates. No accounting functionality is included.

R4 fixes pending links and native NFC admission. URL inputs are controlled local drafts, with visible labels and associated field errors. Invalid/unsupported values remain visible and keep Apply fenced. Correcting commits through actual native validation; Revert link edit discards only that input explicitly, while Discard changes abandons the whole local form. Multiple valid link drafts flush atomically on blur/Apply. Structural edits and local history are fenced while link inputs are unresolved so run addresses cannot drift; the host lease includes those pending inputs. The HTTPS policy is unchanged.

The text session retains the exact raw source as its conflict baseline and editable content after native admission. No NFC transformation runs during typing, selection, paste or grapheme-range editing. Explicit Apply uses the actual native provider's admitted document, including its canonical NFC normalization; untouched open/Apply returns unchanged instead of silently rewriting text. Undo restores the exact prior raw source; reopen after a canonical save uses that saved canonical payload. The form explains this Apply behavior. Heading preservation checks protect level, position and alignment, while native validation owns canonical inline text; comparing a raw NFD heading block with its native NFC output would incorrectly reject accepted text. Genuine external-content/owner/selection conflicts remain fenced.

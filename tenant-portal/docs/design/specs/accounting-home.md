## 1. Workspace Architecture & Zero-Role Composition Rules

### 1.1 Operational Cockpit Principle (`D-175`, `05_Flows/00_Overview.md` §2–§3, `ui-ux-pro-max`)

`/accounting` (`TENANT_ROUTES.accountingHome`) is an **action-first operational cockpit** organized around the accountant's five-stage work loop (`Inbox -> Post -> Reconcile -> Close -> File`), **not** a chart gallery or decorative analytics wall:

1. **Zero role checks in UI code:** The Tenant Portal has **no role concept**. Component code, hooks, and route guards never inspect a role name (`accounting_accountant`, `accounting_cashier`, etc.). Every widget and every button on `/accounting` renders solely from:
   - `user.featureEntitlements[featureKey] === true` (outer entitlement gate from Core `/auth/me`);
   - `user.permissions.includes(permissionKey)` (inner RBAC gate from Core `/auth/me`); and
   - `user.isTenantOwner === true` **only** where Core's `TenantOwnerGuard` applies on `/api/tenant/core/v1/restore-incidents/*` (`12_Platform_Changes.md` §4.10.2). In Accounting itself (`05_Permissions_and_Features.md` §3), `isTenantOwner` holds permissions through role assignment and never bypasses missing `accounting.*` permission keys or maker-checker Segregation of Duties (`D-146`).
2. **Gateway browser routing:** Every `/accounting/...` path from `02_Endpoint_Catalogue.md` is called from the browser through `/api/tenant/accounting/v1/<route>` via `axiosClient`. The Core restore-incident read is called through `/api/tenant/core/v1/restore-incidents/current`. Controller-relative paths and direct service origins are forbidden.
3. **Parallel query isolation (`patterns.md` §8):** All mounted widgets on `/accounting` fetch concurrently through independent React Query hooks (`Promise.allSettled` semantics — never `Promise.all`). A slow, `403`, or `5xx` widget renders its own localized card state without blocking or blanking sibling widgets.
4. **Design-system tokens & typography (`tokens.md`, `typography.md`, `anti-patterns.md`):**
   - Outcome color roles only: `brand`, `positive`, `caution`, `negative`, plus the `ink` neutral ramp (`bg-surface`, `border-line`, `text-ink`, `text-ink-muted`). Status is **never** communicated by color alone — every status badge pairs a semantic tone, an icon, and a localized `t.status.*` string (zero raw wire enums).
   - Font weights: `400` (`font-normal`, table/list cells), `500` (`font-medium`, labels/buttons), `600` (`font-semibold`, card titles & KPI figures). `font-bold` (`700`), `text-[Npx]`, and `rounded-xl` or larger are forbidden.
   - Numeric discipline: Every count, elapsed duration, and monetary string uses `tabular-nums` and `Intl` with Western digits in both locales (`ar-EG-u-nu-latn` and `en-US`). `DecimalString` values from DTOs are formatted without `Number()` conversion. Document/entry numbers, UUIDs, and SHA-256 prefixes wrap in `<IdentifierText>` (`dir="ltr"` / `<bdi>`).

### 1.2 Two-Bar Shell, `AccountingScopeBar`, and Single-Primary-CTA Law

 `/accounting` mounts inside the canonical Tenant Portal shell (`accounting-ia.md` §1.2):

1. **Bar 1 — `GlobalNav` (`45px` + `3px` brand accent strip):** Displays `AppSwitcher` (`المحاسبة` / `Accounting`), `Overview` (`/accounting`), and the six loop menus (`Inbox`, `Post`, `Reconcile`, `Close`, `File`, `Setup`), each filtered by `useNavTree()`.
2. **Bar 2 — `PageActionBar` (`48px`, `primaryPage: true`):**
   - Start edge: Page title `نظرة عامة على المحاسبة` / `Accounting overview` plus live freshness caption (`آخر تحديث: HH:mm` / `As of HH:mm`, using the newest response `asOf` / `timestamp`) and an `outline` `تحديث` / `Refresh` button (`RefreshCw` icon).
   - End edge (**Law 3 — at most one filled `primary` button on the entire screen**): Resolved by a deterministic, role-free permission predicate:
     1. If `hasFeature("accounting.ledger.core") && hasPermission("accounting.journal_draft.read")`: render `primary` CTA **`مسودة قيد جديدة` / `New journal draft`** (navigates to `/accounting/post/journal-drafts`).
        - **Enabled** when `hasPermission("accounting.journal_draft.create") && !isRecoveryMode`.
        - **Shown & disabled with one-line reason** (`accounting-ia.md` §3 Rules 5 & 9) when `accounting.journal_draft.create` is absent (`يتطلب صلاحية إنشاء مسودات القيود (accounting.journal_draft.create)` / `Requires permission accounting.journal_draft.create` — e.g. `approver`, `auditor`) or when `isRecoveryMode === true` (`النظام في وضع الاستعادة` / `Disabled while restore recovery is active`).
     2. Else if `hasFeature("accounting.receivables.core") && hasPermission("accounting.settlement.read")` (when `accounting.journal_draft.read` is absent, e.g. `cashier`): render `primary` CTA **`تسوية جديدة` / `New settlement`** (navigates to `/accounting/post/settlements`), enabled iff `hasPermission("accounting.settlement.create") && !isRecoveryMode` (else disabled with one-line reason).
     3. Else: render **zero** `primary` buttons (only `outline` `تحديث` / `Refresh`).
   - All buttons inside cards (`W-01`..`W-12`) use `variant="outline"` or `variant="ghost"` (`size="sm"`), guaranteeing at most one filled `primary` button on `/accounting`.
3. **Bar 3 — `AccountingScopeBar` (`src/app/(tenant)/accounting/layout.tsx`):**
   - **Company selector:** Binds `x-mutakamel-company-id` (`UUIDv7` from `user.accessibleCompanies`). Required for all `COMPANY`, `COMPANY_OR_BRANCH`, and `BRANCH` widgets. Switching company resets branch/ledger and invalidates React Query prefix `['accounting', tenantId]`.
   - **Branch selector:** Binds `x-mutakamel-branch-id` (`UUIDv7` from `user.accessibleBranchCompanies` for the selected company). Optional filter (`كل الفروع` / `All branches`) when the actor holds `COMPANY` grants; auto-selected and mandatory when the actor holds only `BRANCH` grants (e.g. `accounting_cashier`).
   - **Ledger selector:** Binds `x-mutakamel-ledger-id`. **Hidden** unless `user.featureEntitlements["accounting.ledger.multi_ledger"] === true` (`accounting-ia.md` §3 Rule 3; `PRIMARY` ledger implied in Basic).
   - **Persistent `RECOVERY_MODE` fence slot:** Hosts widget `W-01` / global recovery banner when a restore incident is active (`accounting-ia.md` §3 Rule 9).

### 2.2 Seeded Role Template 1 — Accountant (`accounting_accountant`)

- **Seeded template key (`05_Permissions_and_Features.md` §7):** `accounting_accountant` (typical assignment scope: `COMPANY`).
- **Why this layout renders (no role check):** Under a Basic (`accounting.basic`) or Advanced (`accounting.advanced`) tenant entitlement, `accounting_accountant` holds `"every read"` across `accounting.*` (except the non-`.read` keys `accounting.bank_account.view_sensitive` and `accounting.recovery_incident.approve_correction`, and is not `isTenantOwner`) plus day-to-day posting, intake, settlement, bank-statement matching, close-task completion, and tax-return computation permissions.
- **Omitted widget:** **`W-01`** (`Restore incident & recovery fence` proactive Core poll) is **absent** on initial mount because the user is neither `isTenantOwner` nor granted `accounting.recovery_incident.approve_correction` (`12_Platform_Changes.md` §4.10.2); if the tenant is in `RECOVERY_MODE`, the global `RECOVERY_MODE` banner activates reactively on `403 ACCOUNTING.FEATURE.RECOVERY_MODE` (see `CG-HOME-03`).
- **`PageActionBar` single `primary` CTA:** `مسودة قيد جديدة` / `New journal draft` (`/accounting/post/journal-drafts`) — **enabled** (`accounting.journal_draft.create` held).

## 3. `S2` — The Two Home Measures (`05_Flows/00_Overview.md` §2 & `D-175`)

`05_Flows/00_Overview.md` §2 (*The accountant's day*) defines two operational measures that govern the design of `/accounting`:
1. **Elapsed time from a document arriving to it being posted** (*document arrival to posted*); and
2. **The number of open items on the exception board at the end of a working day** (*today's open exceptions*).

Both render inside widget **`W-03` (`Daily operational measures`)** directly above the work queues. Neither uses a decorative chart.

## 4. `S3` — Per-Widget States & Bilingual Copy (`Cause · Effect · Action`)

### 4.1 State Precedence & Global Design-System State Rules (`docs/design/states.md`, `ui-ux-pro-max`)

Every widget `W-01`..`W-12` evaluates states in strict deterministic order so an operator never mistakes a permission denial, entitlement change, or network failure for "zero work remaining":

1. **`Not-entitled` (`featureEntitlements[key] !== true` or `403 ACCOUNTING.FEATURE.NOT_ENTITLED`):**
   - **Proactive (`/auth/me`):** Per `accounting-ia.md` §3 Rules 1–2, when `featureEntitlements[widget.featureKey] !== true`, the widget is **not mounted (`null`)** and sibling cards reflow cleanly (never greyed out, never badged *"Upgrade to unlock"*). If `accounting.ledger.core` itself is unentitled on direct navigation to `/accounting`, the entire page renders the app-level `UnavailableState`.
   - **Reactive race (`403 ACCOUNTING.FEATURE.NOT_ENTITLED` mid-session before `/auth/me` refresh):** Renders a compact non-promotional `UnavailableState` card with the widget's `Not-entitled` `Cause · Effect · Action` copy and triggers a background `/auth/me` refresh so the card unmounts cleanly.
2. **`403` (`PermissionGate` — `403 ACCOUNTING.SCOPE.TARGET_DENIED` or `PERMISSION_DENIED`):**
   - **Proactive (`/auth/me`):** When `permissions` excludes `widget.readPermission`, the widget is **absent** on `/accounting` (`accounting-ia.md` §3 Rule 4).
   - **Reactive / scope-specific (`403` for the selected `companyId` or `branchId`):** Renders **`PermissionGate`** inside the widget frame (`Lock` icon, neutral `ink` surface — **`403` is never rendered as an empty state**).
3. **`Recovery-mode` (`RECOVERY_MODE` — `403 ACCOUNTING.FEATURE.RECOVERY_MODE` or active incident in `W-01`):**
   - Per `accounting-ia.md` §3 Rule 9 and `12_Platform_Changes.md` §4.10.2, **all read projections (`GET` and read-only `POST .../count` / `.../search`) remain live and visible**, while **all mutating buttons under `/api/tenant/accounting/v1/*`** inside the widget are **disabled** (`aria-disabled="true"`) with a compact inline recovery notice (`Cause · Effect · Action`). Only Core `/api/tenant/core/v1/restore-incidents/*` commands in `W-01` remain enabled.
4. **`Loading` (`Skeleton` — initial mount or `companyId`/`branchId` switch):**
   - Renders `Skeleton` rows matching the exact height and column rhythm of the widget (`aria-busy="true"`, `role="status"`), preventing cumulative layout shift (CLS). Never render a blank white/dark box. Background re-fetches keep existing rows visible and spin only the header `RefreshCw` icon.
5. **`Error` (`ErrorState` — `5xx`, `429`, network timeout, or schema-validator failure):**
   - Renders `ErrorState` inside the widget card (`AlertCircle` icon, `negative` border accent, monospaced `<IdentifierText>` `correlationId` when present, and an `outline` `إعادة المحاولة` / `Retry` button bound to `query.refetch()`). Sibling widgets remain interactive (`Promise.allSettled`).
6. **`Empty` (`EmptyState` — `200 OK` with `0` items):**
   - Distinguishes **operational all-clear** (positive/calm confirmation when a triage queue has `0` open exceptions) from **setup prerequisite** (actionable link when no bank account, treasury box, fiscal year, or return definition exists yet).

**Copy contract (`i18n.md`):** Every string below lives in `src/i18n/ar.ts` and `src/i18n/en.ts` (zero language ternaries in JSX, zero raw wire enum strings, Western digits `0-9` via `ar-EG-u-nu-latn` and `en-US`). Every state message explicitly communicates **Cause (`السبب`)**, **Effect (`الأثر`)**, and **Action (`الإجراء`)**.

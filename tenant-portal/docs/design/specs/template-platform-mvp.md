## Visual contract

- Use existing design-system fonts and tokens, the 45 px top shell, full-width workspaces, horizontal ribbons, floating context controls and centered dialogs. Do not introduce a permanent aside or drawer.
- Support Arabic RTL and English LTR in light and dark themes for every state. Print paper stays white. Document locale and direction are separate from UI locale; Arabic uses Western digits.
- Compare each primary state at the reference PNG dimensions using an overlay, manual review, DOM geometry, contrast and control-state assertions. A numerical pixel threshold alone cannot establish visual or functional acceptance.
- Correct known raster glyph artifacts using canonical labels and fixture data. Record each normalization and preserve all required controls.
- The machine matrix is [visual-acceptance.json](C:/mutakamel.ai/.local/template-design-implementation-2026-11-04/visual-acceptance.json). All cases start as NOT_RUN and NOT_VERIFIED. Its 492 language/theme obligations supplement the 123 primary images.

## Functional contract

Creation uses five steps and server-compatible source, layout, page and starter data. The designer implements typed commands, complete document round trips, Fixed geometry, groups and explicit pages; Flow and Hybrid layout semantics; variable selection and formatting; static and repeating tables; row and column calculations; and a versioned function library. Preserve owner-authoritative financial values and decimal strings. Asset version pins, authorized source selection, safe HTML/email, validation, publication, version restore, scoped assignments, recovery and authorized PDF download are required.

There are 30 semantic starters and 60 localized catalogue entries: seven print families across three layouts, plus three CRM sources with three compositions each. Every design needs actual PDF evidence. Email uses the explicit synthetic EMAIL_PRINT_PROJECTION profile and has no send side effect. Check the email HTML independently at desktop and mobile widths.

An existing definition's immutable source/output/layout tuple cannot change in place. The layout control offers Create converted copy, previews the conversion and creates a new definition/draft. Cancel and undo preserve the source and its published history.

Recovery is scoped to tenant, actor, template and draft. Persist editor content and necessary safe revision metadata only. Do not persist credentials, source-record snapshots or download capabilities. Clear inaccessible recovery on logout, tenant/account switch or total read revocation; losing edit permission while retaining read access is a separate state.

## Evidence and execution

Use an isolated client session on the existing shared Playwright MCP service against the portal on port 5002. After product changes, rebuild the actual production portal before accepting live results. Use genuine authorized server success. Controlled fault injection proves negative UI behavior only and cannot substitute for backend integration.

Each case requires before/after screenshots, accessible DOM state, a sanitized request/response outcome, persisted readback or immutable output where relevant, keyboard/focus evidence and a manual visual verdict. Keep credentials, cookies, authenticated storage state and private source payloads out of artifacts. The already-approved design references need no second approval.

The authoritative PDF preview must load the real Worker PDF and its authorized `TemplateLayoutReceiptV1`, using the new safe `layoutProof` metadata. The runtime-owned pinned Paged.js adapter supplies provisional local pagination feedback only. An unfinished pass or mismatch remains visible; local preview never certifies final PDF parity. Its early browser/layout proof is a prerequisite to dependent pagination acceptance.

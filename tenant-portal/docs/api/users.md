# Tenant Users API

Base paths: 
- `/tenant/users`
- `/tenant/directory`

This module manages the lifecycle, identity, directory profiles, and exact-scope role assignments of tenant users.

## Self Management

### `GET /tenant/users/me/profile`
Returns the authenticated tenant user profile preferences.

### `PUT /tenant/users/me/profile`
Merges the authenticated tenant user profile preferences.
- **Body**: `UpdateTenantProfileDto`

### `GET /tenant/users/me/webphone`
Returns the authenticated tenant user WebRTC phone extension config.

### `GET /tenant/users/me/webphone/call-logs`
Returns the latest tenant WebPhone call logs for the authenticated user.

### `POST /tenant/users/me/webphone/call-logs`
Stores one call log generated by the floating tenant WebPhone.

## Tenant User Management

### `POST /tenant/users`
Creates an invited tenant user, validates organizational placement, and sends an invite email.
- **Permissions**: `users.user.invite`
- **Body**: `CreateTenantUserDto`
- **Response**: `201 Created`

### `GET /tenant/users`
Returns tenant users visible to the current actor, with optional search, pagination, placement, and status filters.
- **Permissions**: `users.user.read`
- **Response**: `200 OK` (Paginated Users)

### `GET /tenant/users/:id`
Returns one tenant user.
- **Permissions**: `users.user.read`
- **Response**: `200 OK`

### `PATCH /tenant/users/:id`
Updates tenant user identity, placement, manager, and job metadata.
- **Permissions**: `users.user.update`
- **Response**: `200 OK`

### `PATCH /tenant/users/:id/webphone`
Updates one tenant user WebRTC phone extension.
- **Permissions**: `users.user.update`
- **Response**: `200 OK`

### `POST /tenant/users/:id/suspend`
Suspends a tenant user, increments their session version, and blocks future authenticated actions.
- **Permissions**: `users.user.deactivate`
- **Response**: `200 OK`

### `POST /tenant/users/:id/activate`
Re-activates a suspended tenant user.
- **Permissions**: `users.user.deactivate`
- **Response**: `200 OK`

### `DELETE /tenant/users/:id`
Soft-deletes a tenant user after validating self-management and tenant-owner protections.
- **Permissions**: `users.user.delete`
- **Response**: `204 No Content`

## Team Memberships

### `GET /tenant/users/:id/team-memberships`
Returns team memberships for one tenant user.
- **Permissions**: `users.user.read`

### `PUT /tenant/users/:id/team-memberships`
Replaces the team memberships for one tenant user.
- **Permissions**: `users.user.manage_memberships`

### `POST /tenant/users/:id/team-memberships`
Adds one team membership to the current user membership set.
- **Permissions**: `users.user.manage_memberships`

### `DELETE /tenant/users/:id/team-memberships/:membershipId`
Soft-deletes one non-primary team membership for a tenant user.
- **Permissions**: `users.user.manage_memberships`

## Scope Role Assignments

### `GET /tenant/users/:userId/scope-role-assignments`
Lists role assignments for a given user.
- **Permissions**: `users.user.assign_roles`

### `PUT /tenant/users/:userId/scope-role-assignments`
Replaces the exact-scope role assignments for a given user.
- **Permissions**: `users.user.assign_roles`

## Party Directory

The `tenant/directory` API manages organizations and contacts inside the tenant ecosystem, handling their addresses, methods, and relationships.

### Parties
- **`POST /tenant/directory/parties`**: Create a party (`directory.party.manage`)
- **`GET /tenant/directory/parties`**: List parties (`directory.party.read`)
- **`GET /tenant/directory/parties/:id`**: Get a party by ID (`directory.party.read`)
- **`PATCH /tenant/directory/parties/:id`**: Update party (`directory.party.manage`)
- **`DELETE /tenant/directory/parties/:id`**: Delete party (`directory.party.manage`)

### Party Images
- **`POST /tenant/directory/parties/:id/image`**: Upload image (multipart) (`directory.party.manage`)
- **`GET /tenant/directory/parties/:id/image`**: Download image (`directory.party.read`)
- **`DELETE /tenant/directory/parties/:id/image`**: Delete image (`directory.party.manage`)

### Party Connections
- **`GET /tenant/directory/parties/:id/contacts`**: List contacts (`directory.party.read`)
- **`POST /tenant/directory/parties/:id/contact-methods`**: Add contact method (`directory.contact.manage`)
- **`PATCH /tenant/directory/contact-methods/:methodId`**: Update contact method (`directory.contact.manage`)
- **`DELETE /tenant/directory/contact-methods/:methodId`**: Delete contact method (`directory.contact.manage`)

### Party Addresses
- **`POST /tenant/directory/parties/:id/addresses`**: Add address (`directory.address.manage`)
- **`PATCH /tenant/directory/addresses/:addressId`**: Update address (`directory.address.manage`)
- **`DELETE /tenant/directory/addresses/:addressId`**: Delete address (`directory.address.manage`)

### Roles & Relationships
- **`POST /tenant/directory/parties/:id/roles`**: Add role (`directory.role.manage`)
- **`DELETE /tenant/directory/party-roles/:roleId`**: Delete role (`directory.role.manage`)
- **`POST /tenant/directory/relationships`**: Create relationship (`directory.relationship.manage`)
- **`DELETE /tenant/directory/relationships/:relationshipId`**: Delete relationship (`directory.relationship.manage`)

### Directory Settings
- **`GET /tenant/directory/settings`**: Get directory settings (`directory.settings.manage`)
- **`PATCH /tenant/directory/settings`**: Update directory settings (`directory.settings.manage`)

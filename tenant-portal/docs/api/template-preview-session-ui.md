The UI:

- Chooses only server-discovered sample fixture keys for the current document locale; it sends the exact saved draft revision.
- Validates actual HTTP 202/200, raw Core envelope, UUIDv7 command/job identity, exact definition/draft/revision/content checksum, compiled checksum and immutable job creation/input-expiry tuple.
- Validates nonnegative attempts, positive lifecycle revisions, canonical artifact URL, output checksum, positive size/page count and actual renderer/browser pins. Regressed lifecycle responses and mutated terminal outputs are rejected.
- Retains the original request body, source and idempotency key when a create outcome is unknown. Explicit recovery resends that exact request; no background write retry or reconciliation route is invented. Definite validation refusals and terminal worker failure allow a new explicit request.
- Polls sequentially every two seconds, pauses after sixty nonterminal responses, resumes the same job and labels a local stop as stopping status checks. It never calls a nonexistent server cancellation API.
- Exposes Core's actual attempt count, including zero, and `nextRetryAt` in the interface locale. T07 integration R2 can retry a missing infrastructure dependency before acquiring a numbered render attempt. No polling count or client action becomes a render attempt. `nextRetryAt` describes server execution; it does not authorize another create POST or prescribe a new browser polling API.
- Retires requests, timers and visible output on owner/revision/fixture/actor/scope/auth changes. The T01 current/ready predicate and stored transport session are checked again before adopting responses and before downloading.
- Clears expired output while idle and checks expiry again on every action. All eventual sibling artifacts must share the same owner expiry; none exists in the current DTO to validate or expose.
- Keeps the create/status input expiry separate from `artifact.downloadUrlExpiresAt`. Passing the input deadline alone does not expire an already authorized completed PDF. A 404 resource refusal is shown as unavailable without an existence/tenant explanation, and monitoring recovery checks the original job rather than rendering another copy.
- Reserves a popup on the download click and severs its opener. One authenticated GET to the canonical protected artifact path rechecks access. The portal rejects redirects and checks the exact response URL, PDF MIME, attachment filename, byte count and SHA-256 against the completed job. The read stops if it exceeds the pinned size, up to Core's 25 MiB limit. After rechecking job ownership and expiry, the portal hands the verified bytes to the browser as `template-preview-<jobId>.pdf`. The reservation closes after handoff or failure. The UI can observe the handoff to the browser.
- Uses Arabic/English dictionary entries, semantic design-system tokens, wrapped controls, logical layout, named indeterminate progress and announced error states. Owner filenames stay LTR inside either interface direction.

There is no blob-generated PDF, inline HTML approximation, SourceAcceptance-as-render, placeholder thumbnail, fake receipt, or asserted native-print completion. Receipt/thumbnail/cancel/snapshot/native-print boundaries are visible. The UI's controls are hidden from browser page printing, but no printed document styling or final pagination is claimed.
